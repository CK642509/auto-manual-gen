# agent —— 給 AI 的上下文

對應系列 **Day 16**（上下文設計）與 **Day 29**（打包進 plugin）。

**核心主張**：AI 寫錯 selector 的四種原因裡，只有一種是 prompt 的問題。
與其一直調 prompt，不如把這個目錄補齊。

| 檔案 | 內容 | 解決哪種錯誤 |
|---|---|---|
| `../apps/demo-stream-app/TESTID.md` | 命名規範 | 「知道有標記但不懂語意」 |
| `UI-MAP.md` | 頁面與導覽結構 | 「懂語意但不懂流程」 |
| `STYLE.md` | 正文風格指南：句式、人稱、專有名詞表、全形半形 | 正文品質 |
| `QUIRKS.md` | **這個 App 的怪癖**（例：某開關由後端決定，設 localStorage 無效） | 人要踩三次才記得住的事 |
| `examples/` | few-shot：兩章已審核通過的正文 | 遠勝形容詞式的指示 |

## 兩個原則

1. **少即是多。** 塞整個 codebase 進 context，效果通常不如一份 200 行的精準摘要。
2. **這個目錄本身會過期。** 要把它放進 code review 檢查清單，跟著 code 一起改。

順帶好處：這其實是在為專案建立「機器可讀的規格」，新人上手也快。
